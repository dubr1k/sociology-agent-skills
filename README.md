# Социологические навыки для ИИ-агентов

Русскоязычные рабочие инструкции для разработки анкет и гайдов интервью, анализа качественных данных и опросов, статистических расчётов, сетевого анализа и проверки причинных выводов.

**Семь навыков, шесть адаптаций:** Hermes Agent, OpenClaw, Claude Code, Codex, Pi и Oh My Pi. Для каждой платформы поставляется самостоятельный комплект SKILL.md с инструкциями по исполнению, справочными материалами и уведомлениями о лицензиях. Это навыки агентов, не готовый статистический пакет и не замена исследователю.

## Состав

| Навык | Для чего применять |
|---|---|
| [sociology-research](skills/sociology-research/SKILL.md) | Анализ корпуса интервью, фокус-групп и документов; сравнение позиций, противоречий и институциональных условий |
| [mixed-methods-instrument-design](skills/mixed-methods-instrument-design/SKILL.md) | Разработка и экспертиза анкет и гайдов, операционализация, переходы, когнитивное тестирование, связь количественного и качественного этапов |
| [interim-survey-report-production](skills/interim-survey-report-production/SKILL.md) | Анализ выгрузок опроса, проверка дублей и знаменателей, открытые ответы и воспроизводимый промежуточный отчёт |
| [thematic-analysis](skills/thematic-analysis/SKILL.md) | Тематический анализ: кодирование, построение и пересмотр тем, карта и связь выводов с цитатами |
| [statistical-analysis](skills/statistical-analysis/SKILL.md) | Выбор теста, предпосылки, размеры эффектов, неопределённость и планирование мощности |
| [networkx](skills/networkx/SKILL.md) | Сетевые данные, центральность, сообщества, компоненты и содержательная интерпретация графов |
| [causal-identification-gates](skills/causal-identification-gates/SKILL.md) | Проверка исследовательского дизайна перед формулировками о влиянии и причинном эффекте |

## Установка

Нужны Git и [uv](https://docs.astral.sh/uv/). Сам комплект и его установщик используют только стандартную библиотеку Python. Статистические библиотеки не устанавливаются автоматически.

```sh
git clone https://github.com/dubr1k/sociology-agent-skills.git
cd sociology-agent-skills
uv run --no-project python scripts/build.py --check
```

Проверка должна подтвердить семь навыков и 42 варианта. Далее выберите **один** харнесс и его каталог skills по [таблице совместимости](docs/harnesses.md). Не устанавливайте шесть вариантов в один каталог: их имена совпадают.

Пример для Claude Code в текущем проекте — сначала план, затем запись:

```sh
uv run --no-project python scripts/install.py --harness claude-code --dest .claude/skills
uv run --no-project python scripts/install.py --harness claude-code --dest .claude/skills --apply
```

Параметры `--harness`: `hermes`, `openclaw`, `claude-code`, `codex`, `pi`, `oh-my-pi`. Каталог назначения всегда задаётся явно, чтобы установщик не записал навыки в чужой профиль. Для многопрофильного Hermes указывайте каталог skills нужного профиля, а не автоматически общий каталог.

Можно установить только один навык:

```sh
uv run --no-project python scripts/install.py --harness claude-code --dest .claude/skills --skill thematic-analysis --apply
```

Без `--apply` установщик ничего не записывает. При совпадении имени с существующим навыком установка останавливается **без перезаписи**. Для обновления сначала сравните локальные изменения, сохраните старый каталог вне сканируемого каталога skills, затем установите новую версию. Автоматического удаления и обновления нет.

После установки проверьте обнаружение навыков штатным интерфейсом платформы. Если список кэшируется, откройте новую сессию. Документированные способы загрузки и ограничения приведены в [инструкциях для харнессов](docs/harnesses.md). Не отключайте sandbox или подтверждения ради установки.

## Примеры запросов

**Анкета:** «Используй mixed-methods-instrument-design. Проверь анкету об опыте работы волонтёров: связь вопросов с понятиями, временные рамки, шкалы, переходы. Верни таблицу замечаний и новую версию; исходник не меняй. Пилотаж ещё не проводился».

**Гайд:** «Разработай полуструктурированный гайд интервью с руководителями и исполнителями. Нужны общий блок, ролевые уточнения, нейтральные вопросы о конкретных случаях, распределение времени и план пилотажа».

**Интервью:** «Используй thematic-analysis. Сначала согласуй аналитическую позицию. Прочитай все переданные интервью, сохрани реестр фрагментов и кодов, проверь отрицательные случаи. Каждую цитату свяжи с источником».

**Опрос:** «Используй interim-survey-report-production. Сбор ещё идёт. Проверь структуру выгрузки, пропуски и предполагаемые дубли; правила исключений предложи до расчёта. В каждой таблице укажи основание процентов».

**Статистика:** «Используй statistical-analysis. Сравни группы, учитывая дизайн выборки. Отдели заранее запланированные проверки от разведочных; представь величину эффекта и неопределённость. Не подбирай тест ради значимости».

**Причинность:** «Используй causal-identification-gates. Проверь, позволяет ли наш дизайн говорить об эффекте программы; не оценивай модель, пока не определены сравнение, время воздействия и угрозы идентификации».

## Как устроена адаптация

- `skills/` — общее русскоязычное содержание без зависимости от харнесса.
- `adapters/` — шесть инструкций исполнения: доступные средства, границы разрешений и работа с файлами.
- `dist/<harness>/skills/` — готовые самостоятельные каталоги. Они включают основной текст, справочники, сведения об источнике и применимые лицензии.
- `dist/manifest.json` — состав сборки и SHA-256 файлов.
- `scripts/` и `tests/` — воспроизводимая сборка, установщик и проверки.

Это **редакционные адаптации**, не полный перевод всех upstream-файлов. Сохранены основные методы и ограничения; платформенные привязки удалены, часть справочников объединена, примеры отобраны. Изменения и происхождение описаны в [SOURCES.md](SOURCES.md) и [SOURCES.json](SOURCES.json).

## Границы и безопасность

- Не называйте анкету валидированной по результатам одного просмотра агентом. Различайте экспертный черновик, когнитивно протестированную версию и полевую версию.
- Не заменяйте реальных участников синтетическими ответами без явного обозначения учебного примера.
- Не загружайте закрытые интервью и персональные данные внешним сервисам без разрешения. Псевдонимизация не гарантирует анонимность текста.
- Установка навыка не предоставляет доступ к аккаунтам, не устанавливает MCP и не отменяет разрешения платформы.
- Вычислительные зависимости устанавливайте в отдельное окружение проекта через uv с явным целевым интерпретатором, не в окружение агента.
- Проверка структуры пакета и копирования файлов не доказывает корректность любого будущего анализа или качество конкретной модели. Тесты запуска всех шести харнессов отдельно не заявлены; см. [отчёт проверки](docs/verification.md).

## Разработка и проверка

```sh
uv run --no-project python scripts/build.py
uv run --no-project python -m unittest discover -s tests -v
uv run --no-project python scripts/build.py --check
```

Редактируйте исходные `skills/` и `adapters/`, затем пересобирайте `dist/`. Сборка заменяет только сгенерированный каталог `dist/`, а не установленные навыки. Не сохраняйте исследовательские данные в репозитории. Предложения по методологии сопровождайте источником и объяснением, какое решение агента меняется.
