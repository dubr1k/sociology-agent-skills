# Обмен графами без незаметных потерь

Сохраняйте схему: класс графа, тип ID, ключи параллельных рёбер, таблицу узлов, порядок матрицы, атрибуты, единицы и правила пропусков. Успешное чтение файла ещё не подтверждает сохранность сети.

## Выбор формата

- CSV/edge list удобен для аудита рёбер, но сам не сохраняет изоляты и атрибуты узлов. Публикуйте отдельную таблицу узлов. Валидируйте заголовки, пустые ID, неизвестные концы рёбер, дубли и конечность чисел. В простом ненаправленном графе A—B и B—A — один дубль.
- GraphML подходит для обмена поддерживаемыми скалярными атрибутами. Списки, словари, None и геометрии требуют отдельного представления. При чтении ID обычно строки; сохранение мультиграфа без фактических параллельных рёбер требует явной проверки типа. Default-атрибуты формата не обязательно разворачиваются на каждый объект.
- GML — текстовый формат, не XML. Типы атрибутов и служебные имена ограничены. Не ожидайте произвольного Python round-trip.
- Node-link JSON содержит узлы, изоляты, рёбра и признаки графа. Параметры имени поля рёбер менялись: проверьте сигнатуры writer/reader в установленной версии и используйте одинаковую схему в обоих направлениях. Не смешивайте служебные ключи ID/source/target/key с пользовательскими атрибутами.
- Матрица удобна для численных алгоритмов, но теряет большую часть атрибутов, а параллельные веса обычно агрегирует. Сохраняйте `nodelist`, направление и единицы отдельно.
- Pickle способен выполнить код при чтении. Не открывайте неизвестные pickle-файлы; это не безопасный обменный формат для публичной коллекции.

## Нулевое ребро и отсутствующее ребро

В плотной матрице ноль часто обозначает отсутствие связи. Настоящее ребро с нулевым весом нельзя тогда отличить без отдельной маски/схемы. Возможность задать иной `nonedge` при обратной конверсии зависит от версии — проверьте API; не копируйте такой аргумент вслепую. В разреженной матрице явно сохранённый ноль и отсутствующий элемент тоже различаются; удаление нулей может изменить топологию.

Числа в целочисленной матрице иногда интерпретируются как кратность рёбер при специальных параметрах мультиграфа. Это не автоматическое восстановление исходных ключей и атрибутов. Для направленного графа строка i / столбец j должна соответствовать i → j; проверьте на асимметричном тестовом примере.

## Проверка после записи

Считайте записанный граф и сравните:

1. Направленность и кратность; множество ID с их типами.
2. N/M, изоляты, петли, ключи параллельных рёбер и ориентацию.
3. Имена и значения нужных атрибутов, их типы и единицы; float сравнивайте с объявленным допуском.
4. Компоненты и одну контрольную метрику, чувствительную к весам.

Проверка только изоморфизма без атрибутов недостаточна. Проверка только N/M тоже недостаточна. Храните файлы как новые артефакты; не перезаписывайте вход без согласования.

XML-форматы читайте из доверенных источников или с проверенной безопасной обработкой XML. Интерактивные HTML-подписи очищайте от недоверенной разметки. SQL-запросы параметризуйте; не подставляйте пользовательский текст в строку запроса. Географические сети требуют проверки CRS, единиц, топологического соединения пересечений и правил направления; координаты линий не гарантируют корректный граф дорог.

Пример реальной проверки GraphML на синтетической сети: [examples.md](examples.md). Документация: [read/write](https://networkx.org/documentation/stable/reference/readwrite/index.html), [конверсия матриц](https://networkx.org/documentation/stable/reference/convert.html).
